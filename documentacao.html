Wash Wizard

Documentação Oficial - Versão Acadêmica Local (SQLite)

Visão Geral do Projeto

O Wash Wizard é um sistema de gerenciamento full-stack desenvolvido para otimizar operações de um lava-rápido. O software controla clientes, veículos, serviços de lavagem, estoque de produtos e fornece um painel financeiro interativo.

A atual versão foi desenhada visando o Projeto Integrador Acadêmico (UNIVESP), removendo a dependência de serviços em nuvem (como Firebase e Supabase) e consolidando a aplicação em uma arquitetura local simplificada (Node.js + React + SQLite).

Arquitetura e Tech Stack

A aplicação segue a tradicional separação Client-Server, dividindo responsabilidades entre o Frontend interativo e o Backend API, que gerencia as persistências.

Camada Tecnologia Responsabilidade
Frontend React 18 + Vite (TypeScript) Interface do usuário (SPA), gerenciamento de estados com contextos, dashboards com Recharts e estilização via Tailwind CSS. Roda na porta 8080.
Backend API Node.js + Express Camada de serviços RESTful, gerencia o CORS, importa/exporta CSV e recebe as requisições CRUD do cliente. Roda na porta 3001.
Banco de Dados SQLite3 Persistência relacional local (armazenado no arquivo raiz wash_wizard.db). Implementa Foreign Keys, constraints e integridade via transações SQL.

Instalação e Execução

O projeto inclui scripts que facilitam a execução paralela de ambos os ambientes (front e back) num único comando.

  1. Instalação de Dependências: 
    npm run install:all
    Instala os pacotes node_modules da raiz, do frontend e do backend.
  2. Configuração: Certifique-se de que o arquivo frontend/.env exista e contenha: 
    VITE_API_URL=http://localhost:3001/api
  3. Execução (Ambiente de Desenvolvimento): 
    npm run dev
    O comando usa concurrently para rodar o Vite e o Node.js em modo watch simultaneamente.

Modelagem do Banco de Dados

O schema foi integralmente adaptado do PostgreSQL para compatibilidade nativa com SQLite, substituindo tipos complexos por strings textuais (ex: uuid e datetime convertidos para TEXT).

  • users Tabela de usuários administradores/operadores.
  • clientes Clientes cadastrados, atrelados ao usuário logado que criou o registro.
  • veiculos Veículos amarrados ao seu respectivo cliente via chave estrangeira `cliente_id` com ON DELETE CASCADE.
  • tipos_lavagem Catálogo de serviços com título, descrição e preço base.
  • lavagens Operações combinando um veículo, tipo de lavagem, status, forma de pagamento e valor.
  • produtos Estoque de materiais utilizados.
  • movimentacoes Histórico de transações de entrada e saída no estoque.

O backend executa o comando PRAGMA foreign_keys = ON; ao inicializar para garantir a integridade referencial nativamente.

Estratégia de Backup (CSV)

O banco oficial é o arquivo wash_wizard.db. No entanto, por requisito do escopo do projeto original, foi mantida a funcionalidade de Backup Flexível via Arquivos CSV.

Exportação: Uma rota no express (/api/backup/export) consulta todas as tabelas e usa a biblioteca csv-stringify para retornar os dados concatenados.

Importação: Múltiplos arquivos (ex: clientes.csv, veiculos.csv) são processados via multer. O backend analisa a ordem correta de injeção baseando-se nas dependências das chaves estrangeiras (primeiro users, depois clientes, etc.), realiza um truncate nas tabelas e re-insere os dados de forma transacional usando BEGIN TRANSACTION;.

Segurança e Autenticação

As requisições frontend criam simulações de autenticação. Administrador e Usuários recebem permissões específicas controladas na interface. Os tokens de sessão persistidos localmente recebem Assinatura HMAC (Hash-based Message Authentication Code), garantindo que alterações mal-intencionadas no localStorage quebrem a validação da sessão e exijam novo login.
